# 90 秒三人合奏剪辑

本片是同一房间内的研究／排练演奏连续选段。画面全部取自给定的四路 HD 代理，保留原构图及正常侧边填充；单画面直接切换，无分屏、字幕、变速或生成动作。

## 交付

- `program.mp4`：1280×720，24fps，2160 帧，90 秒，H.264 / AAC。
- `final_audio.wav`：给定 `master.wav` 的逐字节副本；48kHz、24-bit PCM、单声道、4,320,000 个样本。音频从头到尾连续保留，没有重排、增益处理、淡出或替换。MP4 中只有 AAC 编码带来的有损差异。
- `edit.json`：14 段，完整覆盖 `[0,90)`；同时提供秒数和整数帧数，整数帧字段为重建依据。
- `sync.json`：时间映射、偏移方向、早中晚匹配结果及实际查看的动作证据。
- `rebuild.py`：独立重建脚本，仅依赖 Python 标准库和 PATH 中的 FFmpeg。
- `verify.py`：成片核验脚本，另需 NumPy、SciPy、OpenCV。
- `qa/verification.json`：格式、完整解码、音频波形及逐镜头源画面核验结果。
- `qa/program_contact_sheet.jpg`：每段中点的实际成片抽帧。
- `qa/sync_evidence_A.jpg` 至 `sync_evidence_D.jpg`：每机位三个相隔较远的动作，每次查看前、中、后约 0.4 秒序列。参考与代理有不同视角和不同构图，这些图片只供核验，不进入正式成片。

音视频流的时长均为 90.000 秒。此版本 FFmpeg 的 MP4 容器总时长报告为 90.022 秒，包含 AAC 封装延迟，小于题设一帧容差；视频仍严格为 2160 帧，音乐的有效区间仍是完整的 90 秒。

## 独立重建

在任务根目录执行：

```powershell
python output/rebuild.py
```

重建到其他目录，便于与交付文件分开检查：

```powershell
python output/rebuild.py --inputs inputs --edit output/edit.json --out output/rebuilt --workers 2
```

脚本按编辑表从四路输入准确取帧、编码各镜头、拼接，再合入完整主音轨。中间镜头存放在临时目录，完成后自动清理。不读取现成 `program.mp4`，也不需要 `qa/`、分析缓存、联网或专业剪辑软件。已使用本脚本生成本次交付。支持本机 FFmpeg 4.3.1，采用兼容的 `-vsync 1`；Windows concat 清单入口使用正斜杠路径。

核验交付文件：

```powershell
python output/verify.py
```

## 同步判断

节目零点取参考零点，音频零点也取主音轨零点。全部速率为 1：

| 机位 | 源时间 = 节目时间 + 偏移 | 偏移帧数（24fps） |
|---|---:|---:|
| A，白衣主奏 | +3.000000 秒 | 72 |
| B，酒红衣拨弦 | +1.208333 秒 | 29 |
| C，灰衣手鼓 | +4.000000 秒 | 96 |
| D，合奏全景 | +2.500000 秒 | 60 |

正偏移表示去掉源文件开头的前余量。例如节目 10 秒对应 A 源 13 秒。B 的连续估计约为 1.21 秒，采用最接近的 29 帧。视频保留 24fps，未做运动插帧。

对每个人物区域逐帧计算光流，先在宽范围内搜索运动变化的对应关系，再在节目 3–28、32–57、61–87 秒三个窗口独立核对。右侧高清见证的匹配峰分别约为 A 2.99–2.995 秒、B 1.21 秒、C 3.995–4.005 秒、D 2.48–2.505 秒；D 同时用白衣和酒红衣动作验证。三段间没有显示需要调整速率的漂移。

参考左侧小视角比右侧高清见证的运动对应约晚 60 毫秒，因此以右侧高清见证为主要时间依据，小视角辅助检查动作方向。证据包括白衣约 20.58、44.38、83.38 秒的头部及换把序列，酒红衣约 22.98、39.78、69.78 秒的低头／抬头和拨弦，手鼓约 6.58、49.98、71.78 秒的手部离鼓、轻拍、停驻序列。没有仅凭相同坐姿判断时标。可视对应估计不确定性约 80 毫秒，详见 `sync.json`；光流相关数值本身不代表逐帧测量精度。

如需重新生成分析及对照图（不是重建成片的前提）：

```powershell
python output/analyze_sync.py
python output/make_sync_evidence.py
```

`analyze_sync.py` 可以从输入自行重算人物运动信号；已有缓存时会复用 `qa/motion_*.npz`。删除这些缓存即可完全重算。未使用额外原视频、外部捕获时标、姿态标注或其他运行的数据。

## 选镜头

大部分细节时长给白衣主奏，酒红衣用于呈现真实拨弦织体；手鼓持镜时保留轻拍与停顿，不制造独奏交接。切点参考主音轨局部起音，全部为正常直接切换。最短镜头 2.875 秒，无闪切。以下均是实际 EDL 中的连续稳定镜头：

| 要求 | 节目区间 | 时长 |
|---|---|---:|
| 白衣，0–30 秒窗口 | 5.125–16.250 | 11.125 秒 |
| 白衣，60–90 秒窗口 | 60.250–65.375；79.458–86.708 | 5.125；7.250 秒 |
| 酒红衣，20–50 秒窗口 | 27.042–33.167；40.875–48.958 | 6.125；8.083 秒 |
| 手鼓，55–75 秒窗口 | 65.375–73.583 | 8.208 秒 |
| 开头合奏关系 | 0–5.125 | 5.125 秒 |
| 结尾合奏关系 | 73.583–79.458；86.708–90 | 5.875；3.292 秒 |
