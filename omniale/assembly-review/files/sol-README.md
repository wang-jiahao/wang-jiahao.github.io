# 角磨机装配动作证据交接

交付包含 `actions.json`、`policy.json`、`report.html` 和本说明。动作台账为 **119 条手轨记录（左手 47、右手 72）**，覆盖同一次装配的两段完整视角；双手共同动作分列，所以条数不是物理装配次数。另附数据许可、完整署名和实际检查结果 `validation.json`。

## 打开与回放

推荐在本题根目录（`TASK.md` 所在位置）打开 PowerShell，运行：

```powershell
python output/serve.py --port 8766
```

在 Edge、Chrome 等浏览器打开：

<http://127.0.0.1:8766/output/report.html>

网页不依赖外网或 CDN，动作与口径 JSON 已嵌入网页；直接双击 `report.html` 也可显示全部台账。浏览器若限制本地媒体跳转，使用上述 HTTP 方法。随附 `serve.py` 支持视频跳转所需的 HTTP 字节范围请求；普通 `python -m http.server` 在本机测试中会让跳转回到 0 秒，因此推荐使用随附服务。请保留 `output/` 与 `input/` 的同级关系；视频和录音沿用 `../input/` 的原文件，不重复复制大型媒体。服务仅监听本机 127.0.0.1，按 Ctrl+C 结束。

默认显示全部记录；手别、动作、对象和文本可组合筛选，重置可恢复全部。每条提供正面与俯视回放按钮，使用共享播放器从该条起点播放，到终点自动暂停。下方双手时间条也可选择记录。原生进度条可查看上下文，提供慢放与逐帧前后步进。录音可整段回听，也可点击口径依据区间按钮回听相关交接。

## 最终口径及录音依据

所有事件的 `start_s`、`end_s` 使用 **front.mp4 原片秒数**，`clock` 严格写小写 `front`。口头交接的秒数属于独立的音频时间轴，不是录像动作发生时间。

| 项目 | 最终生效要求 | 交接音频回查范围（约） |
|---|---|---|
| 角色、手别 | 负责人最终决定；解剖左右，分别交付左右手轨 | 0–28.8 秒 |
| 主时钟 | 正面 front.mp4；JSON 写 `front`，不带扩展名 | 28.8–45.4 秒；用 medium 另行复核字母 F、R、O、N、T |
| 第一段 | 原片 0 ≤ t < 83：左右手，`pick_up`、`transfer`、`adjust`、`fit`、`fasten`、`flip` | 56.4–78.4 秒 |
| 第二段 | 原片 83 ≤ t ≤ 173.8：左右手，上述六类另加 `put_down` | 78.4–90.6 秒 |
| 跨界 | 已经开始并跨越 83 秒的动作，按开始时所在的前段口径处理，不切成两次 | 90.6–100.4 秒 |
| 双手、扶持 | 同段同类动作可以左一条、右一条；只是扶住的手不录，`record_holds=false` | 109.9–127.6 秒 |
| 旋拧及结合 | 手指起扣、手拧与工具旋拧均保留；对位和实际插入／贴合分开 | 127.6–159.8 秒 |
| 最后确认 | 操作员提出删去全部取起，负责人明确“不采纳”，重申两段范围、两条手轨并保留取起 | 185.8–214.5 秒 |

操作员约 45.4–56.4 秒的“全段只记右手、删对位、全段删放下”初稿，被负责人否决；约 100.4–109.9 秒的“合并双手为一行、删手指旋拧”建议同样被否决。未把这些建议当成口径。第一、第二段的 `end_s` 是口径边界，不是要求把动作强制截断；82.90–83.60 秒的共同翻面保留两条完整手轨。约 82.4–82.8 秒放下红黄柄工具发生在第一段，依口径未归档；88 秒后重新取起并归还该工具则分别保留取起、放下。

## 方法和编码

仅使用本目录的 `TASK.md`、两个 MP4、交接 WAV、通用 ASR 工具与本题来源许可文件。没有检索数据集原标注、已发布答案、评分、其他实验目录或其他用户会话。

先用本地缓存的 faster-whisper large-v3-turbo 转写完整口头交接，再用 medium 独立复核 28–101 秒关键口径。按角色和明确的否决、确认关系恢复最终要求；ASR 的同音字按任务词汇校正，不把模型生成内容作为录像事实。录音真实长度为 215.264 秒；ASR 尾部可能产生超出媒体时长的幻觉，未采用，也未把转写当逐字核准稿交付。网页保留原录音供复核。

用 FFprobe 确认两个视角均为 H.264、1280×720、30fps、5214 帧、173.8 秒。用 OpenCV 提取完整操作的时间接触表：先按 4 秒通览全片，再按 1 秒补充完整过程、对转换和小件操作按 0.25–0.5 秒细看；83 秒边界附近按 0.1 秒检查。正面确定事件时间，俯视交叉核对手别、取件位置、交接与朝向。抽帧观察不等于对遮挡中的机械状态进行测量。

- `hand` 仅用 `left`、`right`，不使用 `both`。同次转交的递出、接收，以及确实共同执行的翻面等按两手列行；另一手仅持稳时排除。
- `object` 是该手直接操作的对象上位类别。工具旋拧编码为 `fasten + screwdriver/wrench`，手指旋拧编码为对应小紧固件、轴或手柄；受紧固部位写在 `note`，不重复建立同一只手的工具行和目标行。
- 已插轴的机体整体取放、转面仍用 `body`；直接转动外露金属轴时用 `shaft`。细长黑色拨件、金属小件及可能的弹簧统一为 `small_attachment`，不误作最后的长手柄。
- 先找孔、摆正、改变相对位置记 `adjust`；看到送入、压入或贴合才记 `fit`。单纯旋转找位不自动当螺纹紧固。
- 换对象、换动作或明显结束后重新开始分行；同手、同类、同对象的连续旋拧不按往复或换指切碎，未转为其他归档动作且短于 0.8 秒的中断合并。
- 取起包含可见的伸手抓取和移离原位置；放下包含移送、落到支撑面及松手。前段被排除的放下不混入其他动作行。时间记录到 0.1 秒，通常具有约 0.2–0.5 秒的人工边界不确定性，并非机械接触瞬间的精密测量。
- `evidence.file` 按本题根目录解释，例如 `input/front.mp4`。每条同时提供两视角的对应区间；俯视秒数沿用输入的名义同步，未声称实测得到逐帧严格同步，也未擅自加偏移。

## 主要发现与未知项

可回查的操作依次涉及取轴和机体、插合、齿轮状件及小紧固件操作、扳手旋拧、环状适配件靠合、红黄柄螺丝刀旋拧、圆盘总成靠合、绿黑柄螺丝刀旋拧、细长小附件操作，以及最后的取长柄、找孔和手拧。台账按具体可见动作切分，没有用这些大步骤替代逐次索引。

在约 48.2–51.6 秒，右手伸入开口内拨动找位，受动对象被手指和壳体遮住，`object=null` 并说明事实。其他不清楚的具体规格不新设字段或猜名称，统一采用任务允许的上位类别并在备注说明。小件的数量、螺钉头型、工具尖端规格、弹簧／拨件的精确身份及内部是否完全接合均不作推断。`fit` 只表明可见送入／靠合，`fasten` 只表明可见手指或工具旋转；不证明达到规定扭矩、产品合格或运行安全。
