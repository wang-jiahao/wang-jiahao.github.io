# 角磨机装配动作证据交接

本目录是依据 `input/handover.wav` 口头交接、对同一次角磨机装配的 `front.mp4` 与 `top.mp4` 逐段核对后形成的动作台账。两段录像记录的是同一次物理装配，不是两遍操作；文中手别均为操作者的解剖左右，画面没有镜像。

## 最终采用的口头口径

- 第一段 `0.0–83.0 s`：左右手都记录 `pick_up`、`transfer`、`adjust`、`fit`、`fasten`、`flip`；不记录 `put_down` 和 `hold`。
- 第二段 `83.0–173.8 s`：左右手记录上述六类动作，并增加 `put_down`；`hold` 仍不记录。
- 主时钟为 `front`（`policy.json` 中写小写、无扩展名的 `front`），所有时间均以正面录像为准；`top.mp4` 按名义同步时间交叉核查。
- 双手在同一时段做同类动作时，拆为左手一条、右手一条，`bilateral_as_two_tracks=true`，不使用 `both`。
- 跨 83 秒边界的动作按开始时刻所在的半段处理，不切开；本题实际台账在边界两侧各有动作，没有事件跨越 83 秒。
- 单纯扶持、稳定对象不进入台账；手拧和工具旋拧统一记为 `fasten`；对位调整与实际插入/贴合并列时分别记为 `adjust` 与 `fit`。只记录可见动作，不据此判断扭矩、内部接合或运行安全。

## 方法

1. 先复核交接录音的完整语境，区分负责人最终口径与操作员未被采纳的建议：保留取起动作、保留对位、第二段记录放下、双手动作分左右两条、保留手指旋入、不合并为 `both`、不删除取起。
2. 以 `front.mp4` 为时间轴，逐段抽取画面并回看；用 `top.mp4` 核对遮挡处的手别、取放对象和双手配合。遇到工具往复或手部抖动时，按“换动作、换对象或明显结束”划分，不把同一段连续旋拧切碎。
3. 每条事件保留起止秒、执行手、动作、上位对象类别、双视角证据区间和可见事实说明；被遮挡而无法确认的规格、螺纹到位程度、扭矩等不编造。
4. 将同一份事件数据写入 `actions.json` 并内嵌到 `report.html`；网页默认显示全部记录，可按手别、动作、对象和文本筛选，选择事件后可回放主视角片段并切换到另一视角。

## 主要过程与发现

- `0.75–8.60 s`：右手取长轴并转交，左手接住；右手取黑色机体并翻正；左手把轴对准机体孔推入并手指压紧。
- `8.65–37.80 s`：右手取小黑色件并对位、压入、手指旋入；双手两次把机体翻面；右手取扳手在轴/盘端旋拧；左手取黑色大环适配件，对位、套入并手指转动。
- `41.00–82.35 s`：左手取细小银色件并对位、插入、手指旋入；右手取红橙柄螺丝刀长时间旋拧，操作期间左手两次翻面。第一段结束前工具离开工作区，但按第一段口径不记 `put_down`。
- `84.15–88.20 s`：左手取红色 2 号盒的圆盘总成，对位、贴合、压紧。
- `89.15–107.20 s`：右手取青绿柄螺丝刀并旋拧，`106.30–107.20 s` 放回桌面。
- `107.20–159.20 s`：右手先以手指/细长件旋入，左手在红色 3 号盒取小件并对位；双手再次翻面后，右手短暂使用螺丝刀并放下；左手于 `145.00–150.65 s` 取用青绿柄螺丝刀、旋拧后放下，随后继续手指旋拧/压紧。
- `159.25–173.80 s`：左手从红色 4 号盒取黑色长柄，对位并插入/贴合到机体侧面；右手持续转动长柄旋入，录像结束时仍在操作。

共归档 **61** 条事件：左手 29 条、右手 32 条；`pick_up` 14、`transfer` 1、`adjust` 8、`fit` 7、`fasten` 19、`flip` 9、`put_down` 3。第一段 35 条，第二段 26 条；第二段的 3 条 `put_down` 分别为 `e043`、`e049`、`e056`。所有事件均为单手术轨，没有 `both` 或 `hold`。

## 未知项与边界

- 细小紧固件、弹簧/拨件的具体规格和螺纹规格常被手指或工具遮挡，统一使用上位类别 `small_attachment`；不猜测型号。
- 可见旋拧不等于达到规定扭矩或完全到位；台账不判断产品合格、内部接合强度、工具声音或运行安全。
- `top.mp4` 与 `front.mp4` 按名义时间同步使用，个别瞬间的遮挡或运动模糊会影响细部辨认；有疑问处在 `note` 中按可见事实标注。
- `handover.wav` 是后期合成的中文交接（拟制委托），不是现场录音，也不能作为真实工具声音或机械结果的证据。

## 可靠打开方法

推荐在本题根目录运行随附的 Range 静态服务器：

```powershell
python output/serve.py
```

然后打开 <http://127.0.0.1:8000/output/report.html>。该服务器实现了 HTTP Range，浏览器可准确跳转到事件起点；页面默认显示全部 61 条记录，点击“播放”或整行选择事件后，播放器从 `front` 主时钟的起点播放到事件终点，点击“切换视角”可在保持片段位置的情况下查看 `top`，页面顶部提供 `handover.wav` 回听入口。

也可以直接双击 `report.html` 以 `file://` 打开；Chrome/Edge 下视频跳转正常，但浏览器会禁止读取同目录的 `actions.json`，页面将显示构建时的一致性说明。不要用 `python -m http.server`：Python 标准库不实现 Range，浏览器可能退回 0 秒而无法按事件定位。若使用其他静态服务器，请确认其支持 `206 Partial Content` 和 `Accept-Ranges: bytes`。

## 文件

- `actions.json`：61 条动作事件及双视角证据区间。
- `policy.json`：最终口头口径的结构化记录。
- `report.html`：默认全量、可筛选、可逐条回放的交接页面。
- `README.md`：本说明。
- `serve.py`：带 HTTP Range 支持的本地打开脚本，保证视频片段跳转可靠。
