## 检索与音视频核验方法

1. 用 FFprobe 核查流信息；从完整影片建立约每20秒一帧的全片联系图，遍历、筛选与六项委托相关的候选场景。对重复出现的居室、唱机、控制室镜头另做比对，避免仅按场景外观匹配。
2. 对候选连续区间进一步按3秒、1秒、0.5秒取帧；汽车搭扣和把手附近细至0.25秒，并查看原分辨率图确认手部、扣件、表针、头巾和火花。细取帧时间为定位依据，最终 caption 保留原有交叉剪辑，不拼接不相邻段落。
3. 从原片音轨混出16 kHz单声道分析音频：全片用 faster-whisper `small.en` 建立对白索引，六项局部用 `turbo` 复核英语对白及词级时间。对白只保留稳定可确认的含义，不把错词或低声缺词当作完整逐字台词。
4. 使用本地 Qwen2.5-Omni-3B 做分段音轨分析，结合 AST 声音事件分类和画面逐项核对音乐、人声、纸声、冰块硬响、滴答、电话铃、机械嘶鸣、雨刷、短撞击、咳嗽/呼吸等。关键小声和跨镜处另截短窗口复核。此处是基于音轨工具分析的核验，不宣称经过人工现场试听；模型输出中无画面支持的情境推测、错误音源标签、越出窗口的时间和无关续写均未当作事实采用。
5. 尤其区分了三类关系：直接伴随可见动作的短响；声源暂不在画内但连续延伸的声音；先于新画面或跨场景延续的声桥。没有把“画面中有物体”单独当作“音轨听到该物体”，也没有为低微声强定唯一来源。

分析中间结果留在工作目录 `work/`：`transcript.json`、`target_transcript.json`、`audio_observations.json`、`ast_events.json` 及细帧联系图。它们是核查材料，不是附加的确定事实清单；尤其自动音频模型和分类器会有误判，最终采用范围以交付 caption 和各项不确定性为准。

## 回到完整原片

在工作目录用播放器跳至索引表中的标准时间码即可。也可使用 FFplay；例如回看 CAP06：

```powershell
ffplay -ss 4685.8 -t 62.2 -i film.mp4
```

其余项将 `-ss` 替换成起点秒数，将 `-t` 替换成表中时长。完整原片负责最终核查，`evidence/` 视频提供较小的便利副本。
