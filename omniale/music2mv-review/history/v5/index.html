一、任务定义

音乐视频编辑收到一批独立生成的表演候选和两支较长MV。需要结合真实声音与连续画面，判断每个表演候选的同步质量是否可以放行，同时找出MV中需要修改的具体问题，交付带时间依据的审片报告。

独立表演候选

8个候选均包含实际音乐，部分同时带讲话；需结合原声与连续动作判断。分别审查声音起停、接触、持续与休止、口部构音和可见发声。连奏、延音、正常遮挡与合理画外伴奏可以成立。

三、运行轨迹

gpt-6.1-sol

Sol先建立全素材时间索引，再用MusicFlamingo、本地Qwen音频与Whisper辅助判断；对嘴部、触键、字幕和持物动作精查，交付JSON、报告与80份媒体证据。同步决定4/8符合专家多数，新版将已验证的综合发现统一计入召回。

  • MusicFlamingo（nvidia/music-flamingo-hf）：实际分析8个短候选的声部、讲话/歌唱与声音变化。整段长MV推理遇到内存不足，随后尝试30秒窗口；只产出了部分长片窗口结果。
  • Qwen2.5-Omni-3B（本地）：对8个目标音频片段作交叉复核，包含琴音、管乐和MV局部原声；首次生成参数调用失败，改用thinker生成后成功。它被用来读音频，没有调用组织者的Qwen3.8 API求解。
  • faster-whisper · small.en：CPU上转写全部10份音轨并给词级时间。该模型面向英文，自动转写仅作辅助，不能代替非ASR音乐分析。
  • FFmpeg / OpenCV / Pillow / NumPy：完整解码检查、连续时间索引、局部原帧、波形起停及证据裁切；交付自检确认链接和源音轨对齐。

deepseek-v4.1-flash-1017

DeepSeek先遍历全部素材，结合ASR、AST/CLAP声音分类与本地Qwen音频复核，再用嘴部/手部关键点、波形和音高相关性细查同步。期间修复依赖和取帧时间问题，最终7项放行、1项退回，交付JSON与中文报告；局部同步精查较多，综合缺陷覆盖较少。

  • faster-whisper · small / medium / large-v3：多轮转写与局部歌词复核；自动转写仅辅助内容定位，不代表能够识别全部音乐与同步关系。
  • AST / CLAP（本地）：AST声音分类及laion/larger_clap_music音文匹配实际成功，用于区分讲话、歌唱与乐器等非ASR声音。
  • Qwen2.5-Omni-3B（本地）：clip_03与clip_06纯音频推理成功；视频加音频输入因PyAV解码接口等兼容问题未成功。未调用组织者的Qwen3.8 API求解。
  • MediaPipe / Librosa / NumPy：嘴部开合、手指位移、RMS、音高和时间偏移相关性；仅作为感知和核对工具，不把相关系数等同专家同步标签。
  • FFmpeg / OpenCV / Pillow / 原帧查看：音轨提取、联系表和局部连续帧；发现联系表时码矛盾后重新对照源帧。依赖修复占用了部分执行时间。

四、失败分析

gpt-6.1-sol

同步结论仍有两项误放、两项误退

clip_01、clip_02被放行，但专业人工多数为需修改；clip_03、clip_05被退回，多数为通过。两类F1均为0.50，结论部分为17.50/35。专家票仅支持整体同步结论，不能据它捏造某帧或某音符的具体错误位置。

实际取证与最终放行要分开评价

三份独立源片裁判认可了大部分具体声音、连续动作与定位依据；采用票的证据分为13.83/15。最终决定不符合专家多数，不会把真实的取证内容一并清零；反过来，有乐器、有动作也不能替代对整段同步的放行判断。

新增真实问题已计入公共召回

字幕转写、字幕时序、画内文字、吊点和道具变化等发现由源片裁判核验后进入两模型共用参照。采用票覆盖6/7项，综合分46.15/50；不再把未报告黑板这一具体例子视为漏掉整个生成文字根因，招牌等同根有效例子也可覆盖。
